2. **Harness supports:** two nodes (`cloud-two-node.sh:326-327`), in-VPC

3. **Add:**
   - u7s `setup.sh`: second dual-stack subnet in `u7s-test` (e.g.

### (e) MTU (required)

1. **Status:** NOT RUN.
2. **Harness supports:** nothing for MTU; VPC MTU defaults to 1460
   (`setup.sh:54` passes no `--mtu`).
3. **Add (u7s, mostly):**
   - step `mtu-table`: `ping -M do -s N` and `ping -6` stepwise node-to-node
     on the plain path (run 1) and over `wg0` (run 2); `ip -d link` for
     geneve0, wg0 and the NIC.
   - step `bulk-transfer`: backend pod serving a 100 MB file generated with a
     fixed seed (e.g. a busybox `httpd` pod, image pre-pulled in the harness),
     curl from the probe through the front for v4 and v6, `sha256sum` on both
     sides, `ss -ti` retransmit counters on the client during the transfer, and
     a response above (path MTU minus Geneve overhead). Geneve overhead is
     50 bytes over v4, 70 over v6, plus 60/80 for WireGuard; the table should
     show these against 1460.
   - beep: none; if the transfer stalls that is a beep finding (clamping /
     fragmentation), not a harness issue.
4. **Topology:** both runs; uses run 1's and run 2's VMs. Large egress is

## Proposed run plan

Two runs of the extended harness; both `--keep`, then delete by hand with
`vps.sh gc` (also confirm `firewall-rules list --filter=name~u7s-e2e` is
empty).

| Run | Covers | VMs | Duration |
|-----|--------|-----|----------|
| 1 plain underlay, disjoint subnets, dual-stack | (a), (b) Cluster+Local, (d) with negative control, (e-plain) | cp + w1 e2-standard-2 (different subnets), client e2-micro, probe e2-micro (u7s-probe) | 3-4 h incl. install and sonobuoy skipped |
| 2 WireGuard underlay | (c), (e-wg), plus a repeat of (b)-style round trip with (B) | same set; cp + w1 may share a subnet | 2-3 h |

Cost (estimates from memory of Spot list prices, not checked against the
price calculator): e2-standard-2 Spot about USD 0.03/h, e2-micro Spot about
USD 0.004/h, external IPs and egress under USD 1 total for ~200 MB per
direction. Total about USD 1 compute per run; budget USD 5-10 for both with
reruns. Wall time: one operator-attended day. Spot preemption is a risk (the
harness reports exit 3 `PREEMPTED`, `cloud-two-node.sh:107-115`); `--max-run-duration=16h`
is already set (`lib.sh:51`).

Can it be one run? A single run can only host both underlays if it brings up
two clusters (6 VMs) and the harness learns to manage two cp/w1 pairs; this
saves little and complicates failure triage, so it is not proposed. Optional
(f)/(g) would be a third run after `mayor-8w6at.10`.

Implementation order before any run: (1) beep-r2xv merges; (2) u7s adds
`--subnet`, `setup.sh` second subnet, `collect_around`, `--external-traffic-policy`,
Hostname check, negative control, `mtu-table`/`bulk-transfer`, `--wireguard`;
(3) offline logic tests in `scripts/e2e-install/test-cloud-two-node-logic.sh`
(the harness's existing pattern) before spending cloud money.
